# Conventions

Shared rules for all `rcorra68` .NET repositories. When starting a new repo, copy the files in [`templates/`](templates/) (see [templates/README.md](templates/README.md)).

## 🌍 Languages

The language follows the reader.

| Reader | Language | Examples |
|---|---|---|
| Developers | **English** | Code, comments, commit messages, branch names, PRs, issues, changelog, README, workflows |
| End users | **Italian** | UI text, error messages shown on screen, user guides (`docs/guida.md`) |

Domain terms stay **Italian** even in code when a translation would be ambiguous: `Sede`, `Comando`, `Dipendenti`, `CodiceFiscale`, `Estratti`.
English structure + Italian domain term (e.g. `SedeElement`, `FiscalCodeDecoder`) is fine.

## 🌿 Branching (git-flow)

```text
feature/* ─┐
fix/*     ─┼─► develop ──► release/x.y.z ──► main ──► tag vX.Y.Z + GitHub Release
chore/*   ─┘
```

- Work on a branch created from `develop`, open a PR to `develop`.
  Small, low-risk changes may be pushed directly to `develop`.
- **Never commit or open PRs to `main` by hand.** `main` only receives `release/x.y.z` PRs, opened automatically by the *Prepare Release* workflow.
- Ignore GitHub's "Compare & pull request" banner proposing `develop → main`: merging it can delete `develop`.
- A commit already pushed to a shared branch is never amended or force-pushed: fix it with a new commit.
- Delete branches after merge.

Exception: this repository (`reusable-workflows`) has no releases and no `develop`: branches and PRs go straight to `main`. Callers use `@main`, so every merge affects all projects immediately.

Branch names: `<type>/<short-description>` in kebab-case, using the commit types below (`feat/upcoming-expirations`, `fix/csv-encoding`, `docs/readme`).

## 📝 Commits

[Conventional Commits](https://www.conventionalcommits.org/), in English, imperative mood:

```text
<type>(<optional scope>): <description>

<optional body>

Closes #<issue>
```

| Type | Use for | Triggers a release |
|---|---|---|
| `feat` | New feature | ✅ minor |
| `fix` | Bug fix | ✅ patch |
| `feat!` / `BREAKING CHANGE:` | Incompatible change | ✅ major |
| `docs` | Documentation only | ❌ |
| `refactor` | Code change without behavior change | ❌ |
| `perf` | Performance improvement | ❌ |
| `test` | Tests | ❌ |
| `chore` | Maintenance (project files, dependencies, cleanup) | ❌ |
| `ci` | Workflows | ❌ |
| `style` | Formatting | ❌ |

Commits that do not trigger a release are shipped with the next `feat`/`fix`.
Add `Closes #<N>` to the commit or PR description to close the issue on merge.

## 🔢 Versioning and releases

- [Semantic Versioning](https://semver.org/), tags `vX.Y.Z`.
- Version computed by [Nerdbank.GitVersioning](https://github.com/dotnet/Nerdbank.GitVersioning) (`version.json`); never edit it by hand, the *Prepare Release* workflow sets it.
- Changelog generated by [git-cliff](https://git-cliff.org/) on `main` only (`CHANGELOG.md` is never edited by hand).
- Every release publishes a zip per runtime: `<artifact>-vX.Y.Z-<rid>.zip`.

### Workflows

| Caller (in the project) | Trigger | Reusable workflow |
|---|---|---|
| `ci.yml` | every push / PR | [`ci.yml`](.github/workflows/ci.yml): restore, build, test |
| `release.yml` | push to `develop` | [`prepare-release.yml`](.github/workflows/prepare-release.yml): opens `release/x.y.z → main` PR |
| `build.yml` | push to `main` | [`publish-dotnet-cli.yml`](.github/workflows/publish-dotnet-cli.yml): tag, changelog, GitHub Release, sync `develop` |

## 🛠 .NET

- Target the current LTS: **.NET 10** (`net10.0`, `net10.0-windows` for WPF/WinForms). .NET Framework only for legacy apps (`net48`).
- SDK pinned by `global.json` (`10.0.100`, `rollForward: latestFeature`).
- Local tools in `.config/dotnet-tools.json` (`nbgv`).
- Before pushing: `dotnet build -c Release` and `dotnet test -c Release`.
- Use the end-user release (zip from GitHub), never `bin\Debug`. Command-line tools go in `%LOCALAPPDATA%\Programs\Tools` (in the user `PATH`).

## 🔒 Data and secrets

- **Never commit real data** (phone numbers, employee lists, CSV exports) or generated output: keep them outside the repo or in an ignored `data/` folder.
- Commit only examples with fake values, named `*.example.*` (e.g. `docs/estensioni.example.csv`).
- Secrets go in `.env` (`chmod 600` on Linux) or user secrets, never in `appsettings.json`.
- No machine-specific absolute paths in committed files (`launchSettings.json` included): use relative paths.

## 📄 Repository files

Every repo has: `README.md` (English, with badges), `LICENSE` (MIT), `.gitignore` (Visual Studio template + `data/`), `CHANGELOG.md` (generated), and the files from [`templates/`](templates/).
